# SEC-ARCH-02 implementation plan

**Goal:** remove F1/F2 without widening roles rejected by SEC-ARCH-01.

**Approved specification:** Issue #163 decision proposal, Option A, explicitly approved by the owner on 2026-10-15. Implementation owner Codex; independent reviewer Jules.

**Architecture:** retain source provenance while loading grants, calculate a scope for each permission, and bind each request to its required permission's scope. Keep legacy aggregate reach for role eligibility and directory descriptions, never as a substitute for a permission's scope. Use entitlement containment in grant, strict authority, and post-state checks.

**Constraints:** signed commits; isolated branch; no production data changes; preserve explicit deny, role eligibility and global role permissions; no merge before exact-HEAD acceptance and required CI; keep #163 open until merged-main verification.

## Review focus

1. A global read permission must not widen a scoped write or administrator permission.
2. An all-racks read must not widen a selected-rack write, including same-site moves.
3. Granting scope and granting permissions separately must not bypass post-state checks on an empty group.
4. Unsupported data permissions and secondary read gates must not borrow a global role's unrelated permissions.
5. A revoked membership or concurrent authority change must not leave a cached or stale permission scope.
